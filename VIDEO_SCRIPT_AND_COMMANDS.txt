PART 1: THE HOOK & THE PROBLEM (0:00 - 0:55)
================================================================================
[Visual: Camera on you / Facecam + Title slide on screen showing "AI Developer Context OS"]

"Hi everyone, I'm Pratik Singh from NIT Jalandhar.
Today, software engineering is undergoing a massive shift: developers and autonomous AI coding agents—like Claude Code, Cursor, Codex, and Windsurf—are working on the same codebases at the same time.

But here is the massive bottleneck:
1. Every AI tool operates with zero long-term memory. When you switch between Claude and Cursor, all architectural decisions and past resolved bug fixes are forgotten.
2. Even worse: when two developers or AI agents touch the same critical files concurrently, Git has no concept of *agent intent*. Code collisions are discovered only after merge conflicts or broken builds in CI.

To solve this, I built **AI Developer Context OS**: a universal project memory store and conflict-aware Git interceptor designed specifically for multi-agent software development."

PART 2: ARCHITECTURE & AI JUDGMENT (0:55 - 1:45)
================================================================================
[Visual: Architecture diagram from README.md or the terminal]

"Our architecture is built on two core principles:

First: Use AI strictly for semantic understanding and language, but use 100% deterministic logic for safety, locking, and money/code integrity.

Second: Zero developer friction. We provide:
1. A zero-config SQLite persistent store running in Write-Ahead Logging (WAL) mode.
2. A hard token-budget compressor powered by tiktoken.
3. An Model Context Protocol (MCP) server for native Cursor and Claude Desktop integration.
4. A Git pre-push hook that intercepts concurrent pushes in under 12 milliseconds."

PART 4: WHAT BROKE, AND HOW WE GOT OUT OF IT (3:30 - 4:25)
================================================================================
[Visual: Show WHAT_BROKE.md on screen or switch back to camera]

"Now, the most critical part of this build: what broke, and how we solved it.

In our first prototype, we tried to compute live neural embeddings over full multi-file commit diffs synchronously on every git push.
On medium-sized commits, this caused git push to freeze for 6 to 8 seconds! In real life, developers hate latency and would immediately run 'git push --no-verify', making the tool useless.

Here was our recovery:
We decoupled heavy embedding computation from the push interceptor.
1. Agents register their file touch-sets and stated intent asynchronously when their task starts.
2. The Git pre-push hook executes an instantaneous O(1) set-intersection query in SQLite against the active session table.

Interceptor latency dropped from 6,200ms down to under 12 milliseconds—fast, lightweight, and completely friction-free."
